webserv

An HTTP/1.1 server in C++98. One process, one thread, one poll() loop, no external libraries.

If you are reading this in a browser then the server is running, and this page came off the disk through the code in src/. Each link below takes a different path through it.

Things to try

/files/
A directory with no index file, so the listing is generated.
/docs/
Routed with alias, which replaces the matched prefix instead of appending to the root.
/uploads/
Empty until you put something in it. See the commands below.
/cgi-bin/hello.py
A Python script run through CGI, in a forked child, over pipes.
/cgi-bin/env.py?name=world
Prints the environment the server hands a script, query string included.
/cgi-bin/status.py?code=418
The script chooses the status code and the server honours it.
/old-page
A 301, configured with return.
/nothing-here
404, served from the file named by error_page.
127.0.0.1:8081
A second server block on another port. Same process, same loop.

From a terminal

Upload a file, fetch it back, then delete it:

curl -F "file=@notes.txt" http://127.0.0.1:8080/uploads/
curl http://127.0.0.1:8080/uploads/notes.txt
curl -X DELETE http://127.0.0.1:8080/uploads/notes.txt

Send a body in chunks. The server reassembles it before the script sees it, because CGI has no way to express chunked input:

curl -H "Transfer-Encoding: chunked" -d hello \
     http://127.0.0.1:8080/cgi-bin/echo.py

Watch what it is doing while you poke at it:

WEBSERV_LOG=debug ./webserv conf/default.conf

Notes

Requests are parsed incrementally, so one split across many TCP segments costs no more than one arriving whole. Responses resume after a partial send(). CGI children talk over non-blocking pipes in the same poll() set as every socket, and are killed and reaped if they overrun their budget. Nothing in the request path blocks.

Configuration lives in conf/default.conf. The routing rules, the directives, and what is deliberately not implemented are all in the README.
